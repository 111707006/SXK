# #115 身分開關（A_PHONE_IDENTITY）— codebase notes

- 開關：`server.ts` 在 `A_COMPANIES` 旁邊，`A_PHONE_IDENTITY_REQUESTED`／`A_PHONE_IDENTITY`（`resolvePaywallSwitch` 解析，`&& APP_MODE === 'full'`）。啟動訊息在 `app.listen` 裡那串 `if (X_REQUESTED) console.log(...)`（測試不起監聽，驗不到）。
- 簡訊登入：`server.ts` `app.post('/api/auth/sms/verify')`。歸屬由 `resolveCompanyScope(COMPANIES_ENABLED ? req.body.companySlug : undefined)` 定；找帳號走新的 `findLoginAccount(companyId, phone)`（開關開＝`pickPhoneAccount(listUsersByPhone(phone))`，關＝`findUserByPhone(companyId, phone)`）；找不到才 `createPhoneUser(phone, scope.companyId)`。前端送的是 `companySlug`（不是 `c`）。
- B→A 交接接收端：`server.ts` 的 `createHandoffTargetRouter({... findUserIdByPhone, createUser ...})`，路由本體 `src/handoff/routes.ts`。現在 `findUserIdByPhone` 也走 `findLoginAccount(null, phone)`；`createUser` 仍建未歸屬。
- 資料層：`src/db/mysql.ts` `findUserByPhone`（company_key＋phone）、新的 `listUsersByPhone(phone)`（回 id/phone/company_id/has_reports/has_orders，不排序）、`createPhoneUser`、`findUserById`、`findCompanyByUserId`、`findCompanyBySlug`。`users` 表沒有 active 欄（停用 #13 要另加欄或別的做法）。唯一鍵仍是 `uk_company_phone (company_key, phone)` —— 開關開著時兩個「不同 slug、同一支新手機」並發登入仍可能建出兩個帳號（止血版接受；#116 遷移改唯一鍵時才根治）。
- 挑帳號純函式：`src/phoneIdentity.ts` `pickPhoneAccount`（有報告或訂單先、平手 id 最小）。合併重複帳號的遷移預演可以重用它決定「保留哪一個」。
- 測試範本：

  - `test/phoneIdentityProjectB.http.test.ts`（APP_MODE=t1only）、`test/phoneIdentitySwitch.test.ts`（認不得的值）、`test/phoneIdentity.test.ts`（純函式）。
