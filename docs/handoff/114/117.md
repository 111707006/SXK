# #117 合作單位（類型、推薦人代號、個人治療師帳號）— 給後續票的筆記

分支 `impl/117`（worktree `C:\AI project\SXK-wt\a-svc-117`），基於 `a-service-relations`。

## 資料在哪

- **`companies`**（合作公司＝合作單位，A、B 共用同一份 schema）：`id, name, slug(UNIQUE), wecom_webhook_url, logo_url, kind, active, created_at`。
  - `kind ENUM('institution','therapist') NOT NULL DEFAULT 'institution'` 是 #117 加的（遷移 `deploy/migrations/2026-11-23-units-and-referrer-codes.sql`，A、B 兩個庫都跑）。B 的程式碼不寫它（`createCompany(name, slug)` 兩個參數時照舊那句 INSERT）。
- **`admin_users`**：`role ENUM('global_admin','company_member','referrer')`、`company_id`。「單位管理者」＝ `company_member`（名字沒改）。
- **`referrers`**：`admin_user_id(UNIQUE), name, phone, kind ENUM('channel','therapist'), company_id NULL, code NULL, active`。
  - `code VARCHAR(64) NULL` ＋ `UNIQUE KEY uk_referrers_company_code (company_id, code)` 是 #117 加的。NULL 不算重複。
  - `kind` 留著；A 有單位時新建的推薦人不給 `kind` ＝ `therapist`（ADR-0020：不再分）。
- **`referrer_bindings`**：家長為主鍵、綁了不換（#118 起要被服務關係取代）。
- 個人治療師單位：一列 `companies(kind=therapist)` ＋ 一個 `admin_users(role=company_member, company_id=該單位)` ＋ 一列 `referrers(admin_user_id=那個帳號, company_id=該單位, code=NULL, kind=therapist)`。同一個交易（`adminStore.createTherapistUnit`）。

## 程式碼在哪

- `src/admin/units.ts`（前端與伺服器共用）：`UnitKind`、`UNIT_KIND_LABEL`、`isUnitKind`、`isValidReferrerCode`（＝`SLUG_PATTERN`）、`referrerEntryUrl(origin, {companySlug, companyKind, code})`（機構：`?c=<單位>&t=<代號>`；個人治療師：`?c=<單位>`；沒代號／沒單位：null）、`unitsEnabled(shape)`（＝ `isProjectA(shape) && shape.multiCompany`，即 A 且 `A_COMPANIES` 開）。
- `src/admin/adminStore.ts`：`listCompanies`／`findCompanyById`／`createCompany(name, slug, kind?)`／`createTherapistUnit`／`listReferrers`／`findReferrer`（多帶 `companySlug`、`companyKind`、`code`）／`createReferrer({..., code?})`／`setReferrerActive`（推薦人與他的後台帳號一起停——個人治療師的帳號停了連單位管理者也進不來）。撞 UNIQUE 時 `err.dupKey` 是 `'slug' | 'email' | 'code' | 'unknown'`（`tagDuplicate`）。
- `src/admin/routes.ts`：
  - `POST /companies`（`multiCompanyOnly`、`requireGlobal`）：`unitsOn` 時走 `createUnit`：`kind` 必選；`therapist` 要 `email/password/phone`（共用 `readAccountFields`），回 `{company, referrer}`。B 照舊。
  - `POST /referrers`（`requireGlobal`）：`unitsOn` 時 `companyId` 必填、不能是個人治療師單位、`code` 必填且格式對；同單位代號重複 409。A 沒開合作公司／B 照舊（單位選填、不收代號）。
  - `myReferrerId`：`referrer` 角色，或帶 `referrerId` 的 `company_member`（個人治療師）都算推薦人 → `/referrer/codes`、`/referrer/proxy*` 打得到。
- 身分：`src/admin/companyScope.ts` 的 `AdminIdentity` company_member 多一個選填 `referrerId`；`src/admin/adminAuth.ts` 的 `buildIdentity` 在 `findAdminUserById` 的 LEFT JOIN `referrers` 有一列啟用中的推薦人時帶上。`/me` 的 `identity` 多 `referrer: true`（只有這種帳號帶）。
  - **公司條件沒變**：這個帳號看家長仍是 `{kind:'company', companyId}`（全單位）。推薦人白名單 `referrerAccess.ts` 只管 `role==='referrer'`，不管這種帳號。
- 畫面：`src/admin/adminView.ts` 的 `visibleTabs`（A 的 `companies` 分頁叫「合作单位」；`company_member && referrer` 多 `myCodes`、`proxy`）；`panels/CompaniesPanel.tsx`（`units` prop：類型必選、篩選、類型欄、個人治療師帳號欄位）；`panels/ReferrersPanel.tsx`（`units` prop：單位必選且只列機構、代號、個人連結＋`EntryLinkQr`）。`AdminApp.tsx` 用 `unitsEnabled(shape)` 傳。
