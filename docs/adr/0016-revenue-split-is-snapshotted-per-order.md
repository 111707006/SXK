# 清分：每筆訂單開單時記下對方與比例，先算帳、還不打微信分賬

客戶 11/03〈清分〉：收入要在平台、合作公司、治療師之間分。比例一個預設加個別覆寫（每家公司、每位推薦人），
預設平台 20%、對方 80%；合作公司旗下治療師再分一次（公司 20%、治療師 80%）。分的是扣掉微信手續費之後的金額。
改比例只對之後的新訂單生效；只有全域管理員能改，不留修改紀錄。目標是微信支付分賬，但商戶號還沒開通。

## 決定

開關 `REVENUE_SPLIT`（預設關，只在專案 A）。

1. **比例表** `revenue_split_rates`：一組（`scope` ∈ default／company／referrer，`ref_id`）一列，兩個萬分比
   `platform_bp`（平台拿淨額的幾成）、`company_bp`（三方時公司拿「對方那一份」的幾成）。`NULL`＝往上一層找；
   預設那一列沒有就用程式裡的 20%／20%。
2. **誰是對方**（暫採）：家長綁了推薦人就看推薦人 —— 推薦人隸屬合作公司是三方（平台比例看那家公司、公司／治療師看推薦人→公司→預設），
   沒隸屬是平台＋推薦人；沒綁推薦人、帳號歸屬某家公司（進站代號）是平台＋公司；都沒有全是平台的。
   綁了推薦人時不看帳號上的公司。
3. **快照**：開單那一刻（`/api/payment/create`，T2／T3／訓練計劃）算出對方與比例，連同手續費率（`WECHAT_FEE_BP`，暫採 60＝0.6%）
   與對方的名字寫進 `payments.split_snapshot`。寫不進去就 500、不開單 —— 不出一筆沒記比例的單。之後改比例不動舊單。
4. **金額**（對帳時從快照算，`src/revenueSplit/split.ts`）：手續費四捨五入到分；對方的份往下取整，三方時公司的份往下取整、治療師拿剩下；
   所有零頭歸平台。加總恆等於淨額。
5. **後台「清分」**（全域管理員）：改比例、選日期看每筆各方金額與依對方合計、匯出 `.xlsx`（每次記一筆 `admin_exports`，記不下不給檔）。
   對帳只讀 `payments`、帶家長編號，不帶手機號。

## 為什麼

- 規格要「改比例只對新訂單生效」：比例必須跟著訂單走，不能對帳時才去讀現在的設定。
- 對方的名字也記在快照上：公司改名、推薦人停用之後，舊帳還看得出當時分給誰。
- 只算不出錢：微信分賬下單時要帶 `profit_sharing`、事後補不了，且有 30% 上限（見 `docs/reference/微信支付分账与退款-2026-11-06.md`）。
  平台 20%／對方 80% 超過上限，誰當收款方要先問微信，這一份先把帳算對、匯得出來，付款方式定了再接。

## 還沒定的

- **30% 分賬上限**：照現在的比例，平台收款時分出去的超過 30%。要嘛申請高比例、要嘛對方收款、要嘛對方的份走分賬以外的結算。要使用者與微信確認。
- **手續費率**：0.6% 是一般行業費率，以商戶號實際簽約的為準；實際扣多少要對微信帳單。
- **退款**：還在查證（規格「查完再定」）。對帳表上退款的訂單照算原本該分多少、標「已退款」，不進合計。
- 綁了推薦人、帳號上又歸屬另一家公司時算推薦人那一邊 —— 暫採，待確認。
- 0 元訂單、兌換碼換來的使用權不是訂單，不在清分裡。
