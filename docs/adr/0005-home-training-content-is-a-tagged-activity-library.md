# 家庭訓練內容改為一庫多支的活動，依標籤配對

ADR-0003 把干預內容定成**一格一份**：（維度，年齡段，嚴重度）九十格，一格一份圖文步驟，由 `intervention_materials.uk_material_cell` 這個唯一鍵保證。本次改為**一庫多支**：一個活動庫，每支活動帶維度、發現標籤、適齡區間與難度，由配對演算法依孩子的 `T2Findings` 每週選出四支。九十格那套（`intervention_materials` 表與 `interventionMatch.ts` 一線程式）退場。

改動的觸發點是 T2 從「家長填完量表後由人手選一個嚴重度」改成規則引擎自動判定（見 `docs/specs/t2-rules-engine-report-and-video-matching.md`）。規則引擎產出的是**發現標籤**——「表達弱於理解」「觸覺過度反應」「工作記憶」這種東西——而九十格的索引鍵裡沒有一格放得下標籤。繼續走一格一份，等於家長付費做完深度評估之後，交付內容仍然只認得 T1 就產得出的那三個欄位。

## 為什麼不是「兩套並存」

一格一份與一庫多支各有各的道理，把兩套都留著、各自服務不同層級，是本次認真考慮過的選項。否決它的是一個 2026-09-06 查到的事實：

**`intervention_materials` 在正式站有 0 列。** 表在（`migrate-check.txt` 驗證過），程式在，九十格一格內容都沒有。也就是說，`interventionMatch.ts` 從上線到今天沒有服務過任何一列真實資料，而每一位在 A 付費解鎖 T2 的家長，報告第六段看到的都是 `interventionMessage()` 的 `preparing` 那句「这一组训练内容正在准备中」。

這把決定的性質換掉了。原型那 300 筆活動也只有 `name` 與 `age` 兩個欄位，沒有步驟、沒有影片。**兩種模型的內容都是零**，所以這不是「保留既有內容還是丟掉」，是「要委製哪一種形狀的內容」。兩套並存的真正代價因此不是多維護一段程式，而是**要內容團隊同時生產九十份圖文包與三百支活動**。

## 為什麼九十格裝不下這三百支

即使不談成本，形狀本身也不合。原型的適齡字串跨越多個年齡段：`3–8岁`（36–96 個月，300 支裡佔 109 支）同時落在 B 段（24–47）、C 段（48–71）、D 段（72–119）。九十格的索引鍵要求一支活動落進恰好一格，於是這一支得複製成 3 個年齡段 × 2 種嚴重度 = **6 列**，三百支膨脹到一千多列，而改一支活動的一句指令要改六個地方。

唯一鍵在這裡從保護變成阻礙：它當初防的是「同一格有兩份素材、配對取到哪一份看資料庫心情」，但一庫多支的模型裡「同一格多支」正是要的行為，選哪一支由配對演算法決定並附上 `reason`，是可重現的。

## ADR-0003 有哪些決定活下來

被取代的只有**形狀**那一層。以下四條原封不動搬進活動庫，理由沒有一條失效：

- **圖文為主、影片為輔。** 這個 repo 仍然沒有檔案上傳能力，`專案外部依賴清冊.md` 裡仍然沒有物件儲存服務。一支活動的主體是有序的圖文步驟，示範影片是選填的外部連結。家長的網路狀況不是我們能決定的，而這一頁的用途是「現在陪孩子做一次」。
- **網址只收 `https://` 或站內的 `/…` 路徑。** `http://` 的圖在 https 頁面上會被當成混合內容擋掉，後台看起來存好了，家長那邊是破圖而沒有人會收到訊息。
- **只有停用，沒有刪除。** 刪掉會讓「這支活動為什麼不見了」永遠答不出來。
- **不吃 `company_id`，路由以 `requireGlobal` 保護。** 活動庫是森心康的內容，不是家長資料，因此不受 ADR-0001 的公司條件約束。豁免要明列在 `test/adminScope.structure.test.ts` 的 `GLOBAL_TABLES`。

## 一併決定的事

- **這個東西叫「活動」，一整批叫「活動庫」。** 不叫「影片」。規格初稿的 `VideoAsset` 與「300 支影片」是誤導的名字：它會讓內容團隊去準備拍片、讓工程師以為某處已經有影片主機，而上面第一條說得很清楚，兩者都不成立。「影片」在本專案只指一支活動底下那個**選填的示範連結**。詞條與 `_Avoid_` 見 `CONTEXT.md`。
- **不跨年齡段退回、不跨維度退回。** 這是 `interventionMatch.ts` 唯一真正重要的那條規則，逐字保留。把學齡前的精細動作訓練給一歲半的孩子，家長會以為孩子又失敗了一次，而系統從頭到尾沒有一個地方看起來壞掉。配對唯一允許的退路是**同維度同年齡段內**標籤沒對上時退到維度層；再對不上就是「準備中」並導向專家。
- **`intervention_materials` 那張表不刪。** 空表留著無害，刪除遷移是一個沒有回頭路的動作，而它現在的成本是零。

## 後果

- `src/utils/interventionMatch.ts`、`src/utils/materialCells.ts`、`src/utils/interventionPack.ts`、`src/components/InterventionPack.tsx` 與後台的素材庫分頁退場。它們的測試（`test/interventionMatch.test.ts`）中關於**不退回**的那幾條要搬進新的配對測試，不是刪掉——那是這批程式碼真正的資產。
- **正式站在活動庫有內容之前，行為不變**：家長仍然看到「準備中」並被導向專家。這次改的是往後要建什麼，不是現在端出什麼。
- 活動的標籤（`targets`）沒填時，配對只能靠維度層對上，品質退回原型水準。後台要把這件事顯示成進度數字，作法沿用素材庫分頁既有的 `coverageOf`。
- ⚠️ `CONTEXT.md` 記載的**內容債仍然存在**：`sensory_processing` 的 T2/T3 內容實為精細動作、`emotion_behavior` 實為感覺處理。活動庫照維度貼標籤，因此在那幾個維度上，貼標籤的人會照著錯的維度名稱貼。與 ADR-0003 同樣的處置：產品端已知情，先照現狀做。這不是遺漏，是已選擇的取捨。
