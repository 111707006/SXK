# 森心康資安與工程審查清單（2026-10-15）

> 用途：給審查者對著程式碼逐條打勾。這份是**查核項目**，不是發現；沒有任何一條代表程式碼現在有問題。
> 範圍：React 19 SPA、Express 4 單檔 `server.ts`、MySQL（mysql2）、nginx、pm2 單機；家長端簡訊驗證碼登入、後台密碼登入（公司隔離＋全域管理員）、公開報告連結 `/r/:token`、AES-GCM `.ics` 短連結、兩套部署之間的交接密鑰、後台上傳 mp4/jpg 並公開 `/media`（含 Range）、LLM 產報告文字、微信支付（規劃中）、兒童健康資料。

## 二、檢查清單

標記：**[P]** 這個架構特別容易出事、優先查。每條格式：檢查什麼／為什麼／來源。

### A. 驗證與 session（簡訊驗證碼、token、後台登入）

| # | 檢查 | 為什麼 | 來源 |
|---|---|---|---|
| A1 | 驗證碼用 `crypto.randomInt`／`randomBytes` 產生，不是 `Math.random`；至少 6 位數字 | 可預測的碼等於沒有碼 | ASVS 6.5.3、6.5.4、11.5.1 |
| A2 | 驗證碼有短效期（≤10 分鐘）、**用過即作廢**、再索取一次舊碼作廢 | 防重放、防舊碼累積可猜窗口 | ASVS 6.5.1、6.5.5；CS:Multifactor「OTP Handling and Storage」 |
| A3 | 驗證碼綁定「這個手機號＋這個公司歸屬」，不能拿 A 的碼驗 B | 帳號是以（歸屬、手機號）找的，綁錯會跨租戶登入 | ASVS 6.6.2 |
| **A4 [P]** | **每一組碼**有嘗試次數上限（例如 5 次錯就作廢），而且次數記在伺服器（DB），不是記憶體；上限同時按手機號與 IP 算 | 6 位碼只有 100 萬種，沒有「按碼」的上限，限流再嚴也能被分散式猜中 | ASVS 6.6.3、6.3.1；WSTG-ATHN-03；NBP 6.12；CS:Credential Stuffing |
| **A5 [P]** | **索取**驗證碼：按手機號（冷卻＋日上限）、按來源 IP（IPv6 截 /64）、全站每日總量三層；`SMS_IP_DAILY_MAX=0` 真的能一鍵停發 | 簡訊轟炸（打擾第三人）與帳單攻擊（錢）；換號碼擋不住，要按來源 | ASVS 2.4.1、6.1.1；API4:2023；API6:2023；CS:Bot Management |
| A6 | 驗證碼在 DB 存雜湊（或至少不可被讀取端點回傳）；除錯模式 `SMS_PROVIDER=console` 在正式環境啟動即報錯 | DB 或日誌外洩時不等於全站可登入 | ASVS 6.5.2；CS:Multifactor |
| A7 | 驗證失敗訊息、HTTP 狀態、回應時間，對「號碼存在／不存在」「碼錯／碼過期」不可區分到能列舉帳號 | 帳號列舉；兒童資料站尤其敏感 | ASVS 6.3.8 |
| A8 | 比對 token 簽章、碼、`HANDOFF_SECRET`、後台密碼雜湊一律 `crypto.timingSafeEqual`（先比長度） | 計時側信道 | ASVS 11.2.4 |
| **A9 [P]** | 自簽 bearer token：演算法與密鑰固定寫死、簽章在解析 payload 之前驗、必含 `exp`、不接受空簽章或可選演算法；`SESSION_SECRET` 缺失或太短（<32 bytes）時**程式起不來** | 自製 token 最常見的洞是驗簽順序與缺 exp | ASVS 7.2.1、7.2.2、9（自含 token 章 `0x18-V9`）；CS:JSON Web Token；WSTG-SESS-10；PATT:JWT |
| **A10 [P]** | token 有**絕對**存活上限與閒置上限，數字寫在文件；更新（refresh）時換新 token | 一個 token 洩漏後的可用窗口＝存活時間 | ASVS 7.3.1、7.3.2、7.2.4；NBP 6.11（Expire JWT）；WSTG-SESS-07 |
| **A11 [P]** | **伺服器端撤銷**：登出、帳號停用／刪除、管理員停權後，舊 token 立刻無效（DB 查 `token_version`／`revoked_at`，或黑名單）。若現在唯一手段是換 `SESSION_SECRET`，要有明文紀錄這個取捨 | 無狀態 token 預設撤銷不了；家長手機遺失時沒辦法 | ASVS 7.4.1、7.4.2、7.4.5；NBP 6.11；WSTG-SESS-06 |
| A12 | 登入成功一定發新 token，不沿用登入前的任何識別 | 防 session fixation | ASVS 7.2.4；WSTG-SESS-03 |
| A13 | token 放在哪（localStorage／記憶體／cookie）？若在 localStorage，XSS 就等於接管；至少要有嚴格 CSP＋全站沒有 `dangerouslySetInnerHTML` 吃外來字串 | 前端儲存的 token 是 XSS 最大獎品 | ASVS 14.3.3、14.3.1；WSTG-CLNT-12；CS:Session Management |
| A14 | token **不進 URL**（query／path）。已知例外：`.ics` 的 `?t=`、`/r/:token`、`#code=`／`#invite=`（片段）——逐一確認各自的洩漏面（見 I6、P 區） | URL 會進 nginx 日誌、Referer、瀏覽器歷史、微信分享 | ASVS 14.2.1 |
| A15 | 後台密碼：bcrypt／scrypt／argon2（不是 SHA／MD5／明文）；成本參數合理；不限制字元類型、允許 ≥64 字 | 後台＝全部兒童資料 | ASVS 11.4.2、6.2.1、6.2.5、6.2.9；NBP 6.8；CS:Password Storage |
| A16 | 後台登入：失敗鎖定／遞增延遲、無預設帳號（`admin/admin`、種子帳號）、**全域管理員要第二因子**或至少 IP 限制 | 全域管理員一個密碼擋住全站 | ASVS 6.3.2、6.3.3、8.4.2；WSTG-ATHN-02、ATHN-11 |
| A17 | 後台 token 與家長 token **不可互通**（不同密鑰或 `aud`／type 欄位），家長 token 打後台端點一律 401／403 | 簽章同一把 `SESSION_SECRET` 時，欄位混淆＝提權 | ASVS 7.2.2、8.2.1；A01:2025 |
| A18 | 簡訊當唯一因子的風險（SIM 換卡、手機號回收給別人）有文件化接受，且號碼回收後的舊帳號有處理方式 | 兒童資料綁手機號，號碼易主＝資料易主 | ASVS 6.6.1；CS:Multifactor「SIM Swap」 |
| A19 | 若沒有 cookie 認證，確認真的**沒有**任何路由因 cookie 就認人（否則 CSRF 要補）；若有 cookie 則 `Secure`／`HttpOnly`／`SameSite`／`__Host-` | Bearer header 天然免 CSRF，混用就破功 | ASVS 3.3.1–3.3.4、3.5.3；WSTG-SESS-05、SESS-02 |

### B. 授權（IDOR、多租戶、管理員、mass assignment）

| # | 檢查 | 為什麼 | 來源 |
|---|---|---|---|
| **B1 [P]** | 每個路由都有顯式的授權檢查，**預設拒絕**；新增路由沒被歸類就測試失敗（專案已有 `t2TrainingGate`／`adminScope.structure` 這類結構測試，確認它們涵蓋所有 router，含 `/internal`、`/r/`、`/media`、支付回調） | 漏掛中介層是 Express 最典型的授權洞 | ASVS 8.2.1、8.3.1；A01:2025；API5:2023 |
| **B2 [P]** | 身分只取自 token；body／query／header 裡的 `userId`、`companyId`、`email`、`role` 一律不採信（逐一 grep `req.body.`、`req.query.` 後是否流進 SQL 的身分條件） | 專案已有約定，審查要驗證**每一條** | ASVS 8.3.1；API1:2023；CS:IDOR Prevention |
| **B3 [P]** | **每一條**對家長資料的 SQL（讀、改、刪、單筆 `WHERE id=?`）都帶 `user_id=?`；單筆端點別人的回 404 不是 403／500 | IDOR：猜得到 id 就拿到別人孩子的資料 | ASVS 8.2.2；WSTG-ATHZ-04；WSTG-APIT-02；API1:2023；PATT:IDOR |
| **B4 [P]** | 多租戶：後台任何查詢／匯出／匯入都經公司範圍（`withScope`）；`GLOBAL_TABLES` 清單逐表再確認真的不含家長資料；批次端點（匯出、匯入、簡訊邀請）每筆資料都再驗屬於該公司 | 跨公司洩漏兒童資料＝合作公司間的重大事故 | ASVS 8.4.1；A01:2025；API1:2023 |
| B5 | 全域管理員與公司管理員的差別在**伺服器**判斷（`requireGlobal`），不是前端隱藏按鈕；降權／停用立即生效（下一次請求就擋） | 權限變更延遲＝離職員工仍可進 | ASVS 8.2.1、8.3.2、7.4.2；API5:2023 |
| **B6 [P]** | 所有 PATCH／PUT／批量匯入用**白名單欄位**（專案 `readActivityPatch` 做法），不把 `req.body` 整包展開進 SQL 或物件；對每個寫入端點確認一次 | Mass assignment：塞進 `role`、`company_id`、`paid`、`active` | ASVS 15.3.3、8.2.3；API3:2023；CS:Mass Assignment；PATT:Mass Assignment |
| B7 | 回應只回需要的欄位：後台列表手機號是否遮罩、家長端 API 是否回出 `company_id`／內部旗標／其他人資料 | 過度資料暴露 | ASVS 15.3.1、14.2.6；API3:2023；WSTG-APIT-03 |
| B8 | 後台介面有額外一層保護（獨立主機名、IP 白名單或 nginx basic auth／VPN）；後台與家長端若同源，後台 JS 不隨家長端 bundle 送出 | 縮小暴露面 | ASVS 8.4.2、3.5.4；WSTG-CONF-05；PATT:Insecure Management Interface |
| **B9 [P]** | 付費／功能閘門的白名單（`T2_OPEN_PATHS`、`isTrainingPath`）是**最小集合**；路徑比對用精確比對或正規化後比對，`/api/t2/../`、大小寫、尾斜線、`;` 不能繞過 | 路徑前綴比對是閘門繞過經典 | ASVS 8.2.1、4.1.4；API6:2023；WSTG-ATHZ-02、BUSL-06 |
| B10 | `PAYWALL_FREE`、`PAYWALL_DEMO_OPEN`、`DEMO_LOGIN_CODE` 等「開了就免登／免付」的開關：正式站的實際值已核對，且有啟動時斷言（值不對就起不來） | 一個環境變數＝繞過全站付費或登入 | ASVS 13.4.2、13.3.1；A02:2025 |
| B11 | 只允許每支路由明確支援的 HTTP method；未列出的 method 回 405，TRACE 關閉 | 方法覆蓋與資訊洩漏 | ASVS 4.1.4、13.4.4；WSTG-CONF-06 |

### C. 輸入驗證與注入

| # | 檢查 | 為什麼 | 來源 |
|---|---|---|---|
| **C1 [P]** | 所有 SQL 參數化（`?` 佔位）。grep 範本字串拼接、動態 `ORDER BY`／欄名／表名是否走白名單、`LIMIT` 是否強轉整數 | 注入 | ASVS 1.2.4；A05:2025；CS:SQL Injection Prevention、Query Parameterization；NBP 6.4 |
| **C2 [P]** | **mysql2 的坑**：`pool.query(sql, [req.body.x])` 時，若 `x` 是物件，`?` 會被展開成 `` `key` = value `` 形式（`query` 做字串替換，`execute` 才是真預備語句）。確認進 SQL 的每個外來值先驗證為字串／數字型別，或改用 `execute` | 型別混淆讓 `WHERE phone = ?` 變成條件注入；這是 Node＋mysql 特有 | ASVS 15.3.5、2.2.1；PATT:SQL Injection（Node/mysql 條目） |
| **C3 [P]** | 每個接收 JSON 的路由有 schema（zod／ajv／手寫），白名單欄位、型別、長度、陣列上限、巢狀深度；驗證在伺服器層 | 其餘一切的前提 | ASVS 2.2.1、2.2.2；NBP 6.10；CS:Input Validation；API3:2023 |
| C4 | 對使用者 JSON 做 `Object.assign`／展開／遞迴 merge 的位置：沒有 `__proto__`／`constructor` 汙染；用 `Map`、`Object.create(null)`；JSON.parse 的結果不直接當設定物件 | 原型汙染 | ASVS 15.3.6；CS:Prototype Pollution Prevention；PATT:Prototype Pollution |
| C5 | `req.query.x` 可能是陣列或物件（`?a=1&a=2`、`?a[b]=1`），逐處確認有型別檢查；考慮關閉 extended query parser | HTTP 參數汙染、型別混淆 | ASVS 15.3.7、15.3.5；PATT:HTTP Parameter Pollution |

## 三、最常被忽略、這種架構要優先查的 10 項

1. **簡訊限流在多實例與 `trust proxy` 下是否真的有效**（G1、E6、A4、A5）。記憶體限流在 pm2 多實例下失效，`trust proxy` 設錯會讓全站共用一個 IP 桶或被偽造；「每一組碼的嘗試次數上限」常被漏掉，6 位數碼只有 100 萬種。
2. **所有「永久、不可撤銷」的憑證**（A11、P1–P4、P8、I6）：無法在伺服器端撤銷的 token、永久有效的 `/r/:token`、永不過期的交接碼。重點查 DB 存的是不是雜湊、**nginx access log 是否把 URL 裡的 token 記下來了**、帳號刪除後是否一併失效。
3. **IDOR 與多租戶，加上 mysql2 的物件展開**（B2–B4、C2）：每一條 SQL 都帶 `user_id`／`company_id`；`pool.query` 傳入物件時 `?` 會展開成條件，外來值必須先驗證型別。
4. **內部端點與後台有沒有被公網碰到**（O1、O2、Q2、B8）：`/internal/handoff/redeem` 是否被 nginx 擋掉、Node 是否只聽 127.0.0.1、防火牆是否只開 80／443。
5. **送給第三方模型的兒童資料與跨境**（L5、L6、M4、L1、L2）：Gemini 是境外；姓名與作答進 prompt 是提示注入入口；模型輸出必須當純文字渲染；每用戶日成本上限。
6. **付費閘門與支付回調**（B9、B10、N2、N4、N9）：閘門路徑比對能否繞過；`PAYWALL_FREE`／`DEMO_LOGIN_CODE` 在正式站的實際值；回調驗簽必須用**原始 body**（全站 `express.json` 會破壞它）；回調冪等。
7. **Express 4 的 async 錯誤不會被捕獲，且失敗時要 fail closed**（J2、J3、G8）：未包裝的 async 路由會讓請求懸掛；資料庫不可用時不可退回記憶體模式而放行。
8. **上傳流程的順序與清理**（D1、D3、D5、D7）：先驗身分再讀 body、檔名由伺服器決定並確認路徑落在 `MEDIA_DIR` 內、串流中斷時刪暫存檔、`/media` 不列目錄不跟隨 symlink。
9. **CSP 是否真的存在，以及 token 放在哪**（E1、A13、C10、R1）：token 在 localStorage 時，一個儲存型 XSS（後台員工輸入的文字、LLM 輸出）就能接管家長帳號；確認線上回應有嚴格 CSP。
10. **環境隔離與日誌／備份裡的個資**（H2、I1、O7、M5）：本機 `.env` 指向正式站（真實資料、真簡訊）是已知現況；日誌與備份是第二、第三份兒童個資，保存期限要跟刪除承諾一致。
