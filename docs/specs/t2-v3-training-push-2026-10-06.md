# 線上干預 v3：推送規則與 300 支腳本

> **給接手實作的人**：規格表在 §2；改完之後整套怎麼走在 §3；演算法細節在 §4；資料與 API 在 §6；票在 §9。
> 標 **暫採** 的是客戶文件沒講清楚、本規格先這樣定（§8 集中列出，帶去問客戶）。
> 客戶原文照錄（簡體），其餘為本規格的話。「現在」一律指 master `971ef85`。
>
> **權威**：使用者 2026-10-07「依新檔案優先」—— 這份推送說明與既有規格、既有決定衝突時，**以推送說明為準**。
> 本文件只寫與現行不同的地方；沒提到的照 Keep 規格與 v2.1。

## 0. 一頁結論

客戶 2026-10-06 給了兩份跟線上干預有關的東西：

1. **《推送规则说明书》**：五道關卡（严重程度 → 建议顺序 → 年龄窗 → 能力对应模组 → 编号顺序）、每週 3 支／每月 12 支／三個月 36 支、逐月上移、期末依進步調整。
2. **《影片导引脚本·总册·300 支》**：300 支全部是同一個十段格式（片头旁白、原理、准备、六個分镜、孩子反应、常见错误、降阶升阶、观察指标、收尾旁白、拍摄提示）。逐支核過：
   - 模組一 20 支與 9/23 那份《模组一》逐字相同。
   - 300 支的標題、適齡與手冊（`activityContent.ts`）**300/300 一致**；人物配置只有 017、030、040 三支不同（手冊「全家」「全家」「亲子」，腳本都是「亲子或全家」）。

**最大的改變：挑活動不再看標籤與 `targetMonth`。** 推送說明是「活動適齡區間與月齡窗有重疊 → 依編號由小到大」。`targetMonth`
全部是 NULL、E 表沒來，是現在只能跑 17 支示範片模式的原因；照新規則 300 支馬上都配得到。★ 標籤、`avoidIf`、E 表匯入、
後台標記頁的那幾欄從此**不進配對**（資料與後台畫面留著，見 §7）。

其他跟現在不同的：每週 3 支（現在 4）、名額按月照權重分（現在每週 refer 2／watch 1）、固定順序換一套、九維全綠只配前三、
沒做量表的維度用 T1 推定顏色也配、三個月一次排好並逐月上移、每月換「简单／标准／难一点」做法、期末依完成率調整下一期。

## 3. 改完之後怎麼走

1. 家長打開「線上干預」那一頁、`GET /api/t2/weekly-plan`。
2. 找這位家長**目前的一期**（§6.1）：
   - 沒有、或最新報告快照換了（`findings_id` 不同）→ 以這一週為第 1 週開**新的一期**，`adjustment = 'none'`。
   - 有，而且這一週落在它的 12 週內 → 用它。
   - 有，這一週已經在第 12 週之後、快照沒換 → 依上一期的完成率開**下一期**（§5.2）。
3. 開一期＝呼叫純函式 `planPeriod(...)` 一次排好 36 格，整份存進 `t2_training_periods`；之後不再重算（活動停用的處理見 §4.6）。
4. 這一週的 3 支＝那份計劃裡這一週的三格；`t2_weekly_plans` 照舊每週寫一列（打卡統計、歷史都讀它）。
5. 換著玩（K08）照舊回，但候選改成「同一能力、這個月窗口內、不在這一期 36 格裡」，依編號取前 `ALTERNATES_PER_DIMENSION` 支（**暫採**，推送說明沒提）。

## 4. 演算法（`planPeriod`，純函式）

輸入：`findings`（報告快照）、`t1`（九維 T1 分數，快照裡有）、`ageMonth`（一期開始那週的實足月齡）、`library`、`adjustment`、
`previousPeriodIds`（上一期的 36 支，`stable` 時避開）。輸出：能力表（顏色、來源、窗口、名額、模組）＋ 12 週 × 每週 N 格。同輸入兩次結果相同。

### 4.1 顏色（P01）

| 能力的 T2 判定 | 顏色 | 來源 |
|---|---|---|
| `refer` | 紅 | T2 分級 |
| `watch` | 橙 | T2 分級 |
| `clear` | 綠 | T2 分級 |
| `partial`／`not_assessed`／`no_tool` | 依 T1 得分率 | **T1 推定** |
| `not_screened` | 不參加 | — |

T1 推定（原文「88 分以上算绿、56 到 87 算橙、56 以下算红」）：得分率 ＝ T1 分數 ÷ 8 × 100，**≥ 88 綠、≥ 56 橙、其餘紅**。
換成分數：**8 綠、5–7 橙、0–4 紅**。注意 87.5（7 分）落在原文「87」與「88」之間，取橙。

> ⚠️ 這張表跟 A 的 T1 報告三級（8 正常、6–7 臨界、≤5 遲緩）**不一樣**：5 分在 T1 報告是遲緩、在這裡是橙。照「新檔案優先」，
> 活動用這張表，T1 報告不動。量表推薦規格書又是第三種（7 未見明顯、5–6 輕度），見另一份規格。三種讀法各管各的，不要共用函式。

T2 判定的「0 分正常／1–2 分轻中度／3 分重度」對到我們的三級：`clear`＝0、`watch`＝1–2、`refer`＝3。

### 4.2 月齡窗（P03、P11）

- 年齡段沿用 `ageKeyOf`（`<12`、`12-36`、`36-72`、`72+`），月齡用**一期開始那週的實足月齡**（訓練是現在要做的事；v2 的那條註解沿用）。
- 整期窗口 `[lo, hi] = [max(0, m + off[0]), max(0, m + off[1])]`，`off = OFFSET[顏色][年齡段]`。
- 月 k（k＝1、2、3）的窗口：`s = (hi − lo) / 3`，`[lo + (k−1)s, lo + ks]`，小數照留。例：24–36 → 24–28、28–32、32–36（原文例子）。
- 綠色窗口上下都有（36–72 是 ±6），會給到比孩子月齡大的活動 —— 原文就是這樣，照做。

### 4.3 名額（P08、P09）

每月名額 `Q`（預設 12；`adjustment = 'hard'` 時 8，見 §5.2）。

1. 參加的能力 ＝ 紅、橙的全部。一個都沒有 → `PUSH_ORDER` 裡前三個「不是 `not_screened`」的能力，當綠。
2. 權重 紅 3、橙 2、綠 1；`exact[d] = Q × w[d] / Σw`；`n[d] = round(exact[d])`（.5 進位）。
3. 夾到 `[1, 6]`（`Q = 8` 時上限 4，一半）。
4. 總和不等於 `Q` 時一支一支校正：
   - 太多 → 從「`n − exact` 最大」的減一（不低於 1），同值取 `PUSH_ORDER` 較後者。
   - 太少 → 給「`exact − n` 最大」的加一（不超過上限、而且只給 `exact > n` 的），同值取 `PUSH_ORDER` 較前者。上限擋下來的名額**不轉給輕的能力**（不然綠色會拿得跟紅色一樣多），走第 5 步。
5. 上限擋住、加不到 `Q`（例：只有一個紅色能力，最多 6 支）→ **暫採**：依 `PUSH_ORDER` 補進下一個還沒參加的能力（當綠、權重 1），重跑 2–4，直到湊滿或九個都進來。原文「每个月固定 12 个」與「单一能力最多 6 个」在只有一個能力時互相矛盾，帶去問（§8 第 2 題）。
6. 參加的能力比 `Q` 還多（`hard` 時 `Q = 8`、九個都紅）→ 保留排在前面的 `Q` 個（**暫採**，待問表 P-12）。
7. 三個月用同一組名額（顏色在一期內不變）。

驗算原文例子：權重 3、3、2、2，`exact` 3.6、3.6、2.4、2.4 → 4、4、2、2 ＝ 12。九個全紅：各 1.33 → 各 1 ＝ 9 → 加三支給语言、动作、认知。

### 4.4 交錯（P10）

每個月：參加的能力依（顏色重→輕、`PUSH_ORDER`）排好，用**平滑加權輪詢**接成長度 `Q` 的序列（每一步每個能力的累積值加上
自己的名額、取最大的出一支、扣掉 `Q`；同值取排前面的），依序切成 4 週 × 每週 `Q/4` 格。原文例子 4／4／2／2 → 第 1 週 语认注、
第 2 週 感语认、第 3 週 语认注、第 4 週 感语认。一輪一輪發的話 6／3／3 第 4 週會整週同一個能力，所以不用那個。
兩個以上能力參加時每週至少兩個能力（測試窮舉幾種名額組合）。

### 4.5 每一格取哪一支（P05–P07）

對每個能力、每個月，候選清單 ＝ `library` 中 `active`、`moduleNo ∈ DIM_MOD[能力]`、`[ageMonths.min, ageMonths.max]` 與該月窗口
有交集（閉區間）的活動，**依編號由小到大**。取的時候跳過這一期已經排進去的（任何能力、任何月）；`stable` 時也先跳過上一期的
36 支，不夠再用。

窗口內不夠 → 放寬（**暫採**，原文只說「放宽月龄限制，但仍然只在该能力对应的模组里挑」）：同模組群、這一期還沒排的活動，依
「活動適齡區間與窗口的距離」由近到遠，同距離**先取比窗口低的**（從做得到的地方開始，沿用 v2「不往上取」的精神），再同就編號小者。
放寬拿到的那一格 `reason.relaxed = true`。

整個模組群都排完了（20 × 4–7 個模組，一期最多 36 支，正常不會發生）或全停用 → 那一格空著、計入 `preparing`，畫面沿用「準備中」那一句。

### 4.6 已排好的活動之後被停用

一期是開始時排好存下的。某一週要寫 `t2_weekly_plans` 時，那一格的活動已停用 → 用同一能力、同一月的候選清單裡下一支還沒排的補上，
寫回 `t2_training_periods`（只改那一格），`reason.replaced = true`。不重排整期。

### 4.7 示範片模式（`TRAINING_SAMPLE_ONLY`）

這個開關（使用者 2026-10-06：正式站先 17 支即可）跟推送說明無關，**照留**：打開時 `library` 先篩成「有示範片的啟用活動」再進
`planPeriod`，模組與窗口照新規則；放寬（§4.5）幾乎每格都會用到，這是預期的。300 支有了腳本之後圖文模式每一支都能跟練，
要不要關掉這個開關由使用者決定（§8 第 7 題）。

## 5. 推送說明裡治療師做的事，在這裡怎麼做

### 5.1 選周期（1 週／1 個月／3 個月）

只做 **3 個月**（36 支）—— 跟 Keep 的 12 週一致。1 週、1 個月兩種是到院當天給家長帶走用的，我們沒有那個場景。

### 5.2 期末檢核（P13）

推送說明是「一期结束后，治疗师在系统上选一个进步状况」。這裡改成**自動判**：

- 完成率 ＝ 這一期 12 週，每週「練過的計劃活動數」加總 ÷（每週格數 × 12）。「練過」＝那一週裡那一支至少一次打卡（沿用 `practiceStats` 的定義，只是分母從 4 改成每週格數、從一個月改成一期）。
- **≥ 80% → `good`**：每個參加的能力顏色往輕一格（紅→橙→綠，綠留綠）重算窗口；三個月都用「难一点」；每週 3 支。
- **50–79% → `stable`**：顏色不動；先避開上一期的 36 支（「只换活动内容」）；做法照月份走。
- **< 50% → `hard`**：顏色往重一格（綠→橙→紅，紅留紅）；每週 2 支（每月 8）；三個月都用「简单」。
- 原文的「多数活动已经能自己做到」「家长的观察记录」：打卡時勾的「怎麼看出有進步」與心情**現在只記錄，不進判斷**（沿用 Keep §9 第 6 題）。300 支都有了觀察指標，之後要接再說。
- 調整只影響活動，不改報告（原文「不会改动量表的评估结论」）。
- 家長重新做了 T2 → 新快照 → 新的一期從 `none` 開始，不帶調整（原文「用真实的评估结果取代这个暂时的位移」）。

### 5.3 交給家長時的叮嚀

原文第九節「交給家長的時候」四句，放到計劃頁上方（先過《用语对照表》掃描）：「這個月一共 12 個活動，一週做 3 個，每個活動一週做 4 次左右，一次 10 到 15 分鐘」等。

### 5.4 紅色能力的轉介

原文「红色能力一定要转介专业评估，家庭活动只是配合」。計劃頁上，有紅色能力時在能力表下方加一句並接 `serviceChoices`（四種服務那一排），字句用既有的 `statusWording`／`reportCopy`，不自己寫新的狀態詞。

## 6. 資料與 API

### 6.1 新表 `t2_training_periods`

```sql
CREATE TABLE IF NOT EXISTS `t2_training_periods` (
  `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  `user_id` INT UNSIGNED NOT NULL,
  `findings_id` BIGINT UNSIGNED NOT NULL,
  `period_no` INT UNSIGNED NOT NULL,        -- 同一份快照的第幾期，從 1 起
  `first_week_start` DATE NOT NULL,
  `age_month` INT UNSIGNED NOT NULL,        -- 開期那週的實足月齡
  `adjustment` VARCHAR(8) NOT NULL,         -- none | good | stable | hard
  `completion` DECIMAL(5,2) NULL,           -- 上一期的完成率（none 時 NULL）
  `plan` JSON NOT NULL,                     -- 能力表＋12 週的格子（§6.2）
  `rules_version` VARCHAR(32) NOT NULL,
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY `uniq_user_findings_period` (`user_id`, `findings_id`, `period_no`),
  CONSTRAINT `fk_t2_training_periods_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_t2_training_periods_findings` FOREIGN KEY (`findings_id`) REFERENCES `t2_findings` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

迁移 `deploy/migrations/2026-10-xx-t2-training-periods.sql`，**先於新版程式碼部署**；`deploy/schema.sql` 同步；不吃 `company_id`（使用者的資料，照 `t2_weekly_plans` 的歸類）。記憶體模式照 `practiceRoutes` 的退路。

### 6.2 形狀

```ts
type PushColor = 'red' | 'orange' | 'green';
interface PeriodDimension {
  dimension: DimensionCode;
  color: PushColor;
  source: 't2' | 't1';           // T2 分級／T1 推定
  baseColor: PushColor;          // 調整前（good/hard 移過一格時與 color 不同）
  window: [number, number];      // 整期
  monthWindows: [[number, number], [number, number], [number, number]];
  quota: number;                 // 每月
  modules: ModuleNo[];
}
interface PeriodSlot {
  week: number;                  // 1–12
  activityId: string | null;     // null ＝ 準備中
  dimension: DimensionCode;
  variant: 'easy' | 'standard' | 'hard';
  reason: { color: PushColor; source: 't2' | 't1'; module: ModuleNo; window: [number, number]; relaxed: boolean; replaced?: boolean };
}
```

`/api/t2/weekly-plan` 的 `activities[].reason` 換成上面的 `reason`（**K08 之前、v3 之前存的舊週次照存的樣子回**，畫面要容許舊形狀：`band`／`matchedTags`／`belowWindow`）。`plan` 加 `periodNo`、`monthIndex`、`variant`、`dimensions`（能力表，給 P17）。

### 6.3 舊資料

- 已存的 `t2_weekly_plans`（每週 4 支、舊 reason）**不回頭改**。上線後第一個還沒存的週次開第 1 期；`weekIndex` 從那一期的第一週算（12 週計數因此重新開始 —— 對已經練到第 5 週的家長，計劃頁會從第 1 週重來，**暫採**，§8 第 5 題）。
- `RULES_VERSION` 換版（活動配對的規則換了）。

### 6.4 開關

`TRAINING_PUSH_V3`（`1`／`true`／`0`／`false`，認不得的值起不來，照 `resolvePaywallSwitch`）。關著時 `weekly-plan` 走舊的
`matchWeeklyActivities`、不讀寫 `t2_training_periods`；開著才走本規格。驗收全部通過後把程式碼預設改成開，正式站要退回就設 `0`。
§7 的「刪掉舊配對」因此延到開關拿掉的那一張票。
