# 微信分账：只分到微信的上限、過了退款期才分、一筆只分一次，其餘記線下結

ADR-0016 的清分只算帳、不出錢。使用者 2026-11-17 要把微信分账接上。

## 微信的規則（官方文件，2026-11-17 讀）

- 開單時要帶 `settle_info.profit_sharing: true` 才能分；帶了之後款項**先凍結**在商戶號，分完或解凍才進可用餘額，最長 30 天（逾期自動解凍、不能再分）。
- 一筆訂單分出去的合計 ≤ 訂單金額 × 商戶平台設的「最高分账比例」（**預設 30%**），且不超過扣手續費後的淨額。
- 接收方要先「添加分账接收方」；商戶接收方要商戶號＋全稱（加密送出），個人接收方要在商戶 AppID 底下的 openid。
- 請求分账是異步的，結果要另外查；分账本身不另收手續費。
- 分账之後退款：要先向接收方「分账回退」，而且只有商戶類型的接收方能回退。
- 沒有沙箱。

來源：產品介紹 https://pay.weixin.qq.com/doc/v3/merchant/4012067962 、接入易錯點 https://pay.weixin.qq.com/doc/v3/merchant/4054257702 、
開發指引 https://pay.weixin.qq.com/doc/v3/merchant/4012068033 、常見問題 https://pay.weixin.qq.com/doc/v3/merchant/4014547102

## 決定

開關 `PROFIT_SHARING`（預設關，只在專案 A，要同時開 `REVENUE_SPLIT`）。

1. **金額照清分快照算，但不超過微信的上限**（`src/profitSharing/plan.ts`）。清分預設對方拿淨額的 80%，遠超過 30%：
   超過的部分各方照比例縮，沒分出去的記成 `offline_fen`（線下結），後台看得到。上限由 `PROFIT_SHARING_MAX_BP` 設，
   **要等於商戶平台的設定**（設得比商戶平台高，微信會整張拒絕）。
2. **有接收方才帶分账標記**。開單那一刻，對方有登記好、微信也添加成功的接收方，而且分得出至少一分錢，才帶
   `profit_sharing`；否則不帶（不白白凍結 30 天）。帶了就在 `profit_sharing_orders` 記一列，記不下不開單。
3. **過了退款期才分**（`PROFIT_SHARING_DELAY_DAYS`，預設 7 天，上限 25 天留給失敗重試）。到期那一刻訂單已經退款就不分 ——
   退款期內退款不必向對方追錢。**分账回退不做**：分出去之後的退款由人處理（個人接收方微信本來就不能回退）。
4. **一筆只分一次**：請求分账一律 `unfreeze_unsplit: true`，剩下的當場解凍回商戶。到期時沒有可分的（接收方停用了）只送解凍。
5. **不會分兩次**：送出前先把單號 `PS<訂單 id>A<第幾次>` 寫進資料庫；微信同一個單號重送等於一次。網路斷了、5xx 留在原狀態、
   下一輪用同一個單號同一份金額再送；業務拒絕變 `failed`，由管理員選「重試」（換單號）或「只解凍」。微信受理過的不能重試。
6. **誰按**：後台「清分 → 微信分账」的「执行分账」按鈕（全域管理員）。定時器 `PROFIT_SHARING_AUTO_MINUTES` 預設關 ——
   把錢轉出去這件事預設要有人按。
7. **個人接收方不存姓名**（微信選填；傳了會做實名比對）。openid 由後台用手機號查（那個人要先用微信在站上走過一次付款授權）。

## 為什麼

- 不改清分的比例來遷就 30%：比例是客戶定的商業條件，分账只是付款管道之一。對帳表照舊是「該給多少」，分账單是「微信付了多少」。
- 延後分而不是即時分：即時分之後的退款要向對方追錢，個人接收方還追不回來。
- 預設手動：分账沒有沙箱，第一次驗證就是真錢。

## 還沒做／已知限制

- **沒有一行打過微信的伺服器**。驗過的是欄位逐個對官方文件、加密解得回來、流程用假的 API 跑過（`test/profitSharing*.test.ts`）。
- 分账回退、分账動帳通知（回調）沒接：結果靠查詢。
- 清分的 `.xlsx` 對帳表還沒有「微信已分／線下結」兩欄，要看後台的分账單。
- 上限 30% 而對方拿 80% 這個落差要使用者決定怎麼辦（申請提高上限、其餘線下結、或改用別的付款管道），見 `docs/ops/2026-11-17-上线待办.md`。
