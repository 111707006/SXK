# T2 v3：題庫換完整版（R3）

> **給接手實作的人**：每支工具長什麼樣、怎麼算、哪裡跟舊版不同，寫在盤點（`docs/reference/T2完整版工具包盤點-2026-10-07/`），
> 這份不重抄；這份只定**做法、規則、暫採、票**。引用推薦規格書寫「客規 §N」，引用接入說明書寫「IT §N」。

## 0. 一頁結論

- 完整版 24 支（客規 T2 層、家長可填）**每一支的資料結構都換了**（GM 從 `SECS/LEVELS` 變成 `SECS/FORMS/OPTS/BANDS/LEVELS/EXCL/FLAGS/CTX`……），
  9/08 的 22 份配方一份都套不上；題目也大多改寫（逐題沿用的只有 AB、SNAP-IV、CHEXI、M-CHAT、VOC 的里程碑段，ADP／LANG／LDP 大半）。
  **等於重做題庫層、計分層、規則層**，規則層以下（維度彙整、報告、線上干預）只換輸入。
- 做法維持現行架構：**抽資料、伺服器算分、自己的作答畫面**，不內嵌客戶網頁（§1，ADR-0010）。這與 IT §七第 5 條「不要在院内系统里重算分数」相反，理由與補救寫在 §1。
- 每支工具的結果先變成**它的主維度的 0–3**（客規附錄 A 的 `primary`），維度判定＝做過的工具裡取最重（R-12 暫採），
  再照推送說明的對法變成三級：0 → `clear`、1–2 → `watch`、3 → `refer`。今天**只有 0｜1–2｜3 這兩條界線有行為上的影響**。
- 新題庫與舊題庫**並存**，由 `T2_RECOMMEND_V3`（R4 的開關）一起切：開著時推薦、作答、報告全走新題庫；關著時一行不動。
- 盤點出來、要客戶回答的有 13 題（§7，待問表 R-15…R-27）；都先照暫採做。

## 1. 做法：抽資料、自己算分（不內嵌）

IT 說明書給的接法是把每支 HTML 放進 iframe、收 `postMessage` 的 `{grade, score, note}`、存工具自己匯出的 JSON，**不重算、不重畫**。我們不照做：

| 內嵌會碰到的 | 盤點裡的證據 |
|---|---|
| 頁面是給治療室用的：必填「评估人员／填表人」、個案姓名、治療師段（EXCL、FLAGS、CTX、觀察活動） | 每支都有 `f_name`；GM 一支「治疗师」出現 18 次；ASR 寫「不建议家长自行填写」 |
| 報告文字不過《家长报告用语对照表》（客戶自己的用字規則） | 分段名稱就有「明显落后」「中度落后」 |
| `postMessage` 的分級跟頁面上不是同一套 | ASB／ASR／AB／ATT／SP／SPb／ADL 兩套切點不同；VOC 永遠不送「重度」；氣質不送 |
| `grade` 是中文字串、`score` 沒有共同量尺（IT §四），終究要我們自己對到 0–3 | — |
| 結果由瀏覽器回報，付費報告的判定要伺服器說了算 | 現行 `scoreTool` 就是為了這個（#57） |
| 開客戶的 HTML 要執行客戶的程式碼；本專案抽題一向「一行都不執行」 | `scripts/t2/literals.ts` 檔頭 |

IT §七第 5 條擋的是「重算算錯、外觀看不出來」。補救：

1. **常數全部用腳本從 HTML 抽**（題目、選項、切點、題組），探針讀不到就停，不用預設值補 —— 客戶換版重跑會炸，不會安靜留著舊數字（沿用 `kit.ts` 的做法）。
2. **計分照頁面的公式一行一行搬**，每支一份測試，在**每一個切點兩側各一組作答**，期望值是讀頁面程式算出來的（測試檔頭註明出自哪個函式、哪一行）。
3. 跟客戶說明我們重算、附上每支的 0–3 對照表請他們看（待問表 R-7，已在問）。

被否決的另一條路（內嵌＋收 `postMessage`）記在 ADR-0010，連同「什麼情況下要回頭」。

### 2.2 月齡、填寫人、分鐘：以客規為準

客規附錄 A 的 `minM／maxM／rater／minutes` 是權威（推薦規格 §1）。HUB 的 `TOOLS`、各頁面自己的年齡檢查只當參考，不一致的列在 §6。

### 2.3 填寫人

客規的填寫人 P（家長）／T（教師）／S（本人）／C（治療師）。在家的情況：

  其中會改變分級的（ASQ3 的 `RED_BANDS`、LQ 的紅旗、ASB 的能力倒退）若家長答得了就問，逐支寫在 §4。

## 3. 資料：新的題庫層

### 3.1 位置與形狀

- 新目錄 `src/t2/kitv3/`：`<代碼>.ts` 由腳本產生、不手改（同 `src/t2/toolkit/` 的規矩）；`index.ts`、`types.ts` 手寫。
  舊的 `src/t2/toolkit/` **原封不動**（開關關著時還在用；舊作答、舊快照也指著它）。
- 形狀比舊的寬：一支工具＝**一個或多個「表」**（form；ASQ3 的 21 個月齡題組、氣質的 ITQ／TTS／BSQ、SP 的 H25／H512 都是表），
  每個表有面向、題目、**每個面向自己的選項組**（LQ 的「不确定」、ADL 的七級、TIC 的 0–5 錨點、氣質的 1–6／1–7＋「不适用」）。
  挑表、挑題的規則（月齡起點、題組、年級）寫成資料，不寫在畫面裡。
- 版本號 `TOOLKIT_VERSION_V3 = 'kit-20260923'`；`t2_tool_results.toolkit_version` 已經有這一欄，不必遷移。`tool_id` 是 `VARCHAR(16)`，最長的 `ITQ/TTS/BSQ` 11 字，放得下。

### 3.2 抽取

`scripts/t2-extract-kitv3.ts`（`--check` 比對），沿用 `scripts/t2/` 的零件，要補三樣：

1. **zip 檔名**：完整版 zip 的中文檔名沒設 UTF-8 旗標 → `readZip(buf, { unflaggedUtf8Names: true })`（已有這個選項）。
2. **字串相加**：EMO、PLE 的資料宣告用 `"…"+\n"…"` 接長字串，`literals.ts` 的純資料檢查要放行「字串 `+` 字串」（仍不許任何識別字）。
3. **第二段 script**：有 13 支把邏輯放在第二個 `<script>`、資料段結尾是 `Object.assign(window, {...})`；收集照舊在第一個非宣告敘述停下。
   切點寫在函式裡的（`LEVELS` 之外的 `if(p>=85)`、LQ 的帶差規則、EMO 的矩陣），照舊用**探針讀原始碼**。

### 3.3 紙本比對

`纸本版/` 31 份 docx 是題目文字的權威（同 9/10 那一次）。`scripts/t2-diff-paper.ts` 加一個 `--kit v3`，24 支逐題比對、印差異；
**差異不擋上線**，列給客戶（9/10 那一次 22 支全零差異）。

## 4. 計分與 0–3

### 4.1 共同規則

- 伺服器算分（`scoreTool` 的 v3 版），規則照頁面；**題目沒出現的不算缺答**（月齡起點以下、別的表的題）。
- 每支吐：各面向的數值、整支的數值、**頁面上的那一套分段**（名稱只進後台與測試，家長端不出，同現行 §5.3），以及 `grade03`（對它每個主維度的 0–3）。
- **用頁面上報告那一套分段，不用 `postMessage` 那一套**（沿用 v2 附錄 D「只抄報告分段＝紙本分數解讀」）。兩套不同的 7 支列在 §6 R-16 給客戶看。
- 分段 → 0–3：**四段**依序 0／1／2／3；**三段**依序 0／1／3（中間那段是「需留意」，最差那段是頁面寫「建议专业评估／进一步评估」的那一段，等同推薦）。
- 只有一個主維度的工具，整支的分段就是那一維的 0–3；多個主維度的（只有 ASQ3），各面向各自分段。
- **沒有主維度的兩支**（`SXK-QOL`、`ITQ/TTS/BSQ`，客規 `primary: []`）不出 0–3、不進維度判定；報告各自一段（§5.3）。

## 5. 維度判定與報告

### 5.1 一個維度的判定（新題庫）

0. 不篩的月齡段（學習 0–36、注意力 0–11）→ `not_screened`（照舊）。
1. 推薦引擎這一次推了、而且主維度含這一維的工具（下稱「這一維的量表」），**都沒有完整的一筆** → T1 紅：`partial`、T1 黃：`not_assessed`、T1 綠：`clear`（照舊三種）。
   引擎沒推任何主維度含這一維的工具、而 T1 紅或黃 → `no_tool`（客規的「缺口」）。
2. 其餘 → 這一維的量表裡**完整的那幾筆取最重的 0–3**（R-12 暫採），0 → `clear`、1–2 → `watch`、3 → `refer`。
   引擎沒推、但家長做過的（近 3 個月內）也算 —— 多看一份不會讓判定變輕。

「這一次推了哪些」存進報告快照（推薦結果在 R4 會存），判定讀快照，不讀當下重算的推薦。

### 5.2 快照與版本

`T2Findings` 加 `toolkitVersion: 'kit-20260923'` 與每一維的 `grade03`（0–3，可為 null）。報告頁看版本決定走哪一套說明；**舊快照照存的樣子讀**（同現行）。

### 5.3 報告畫面要改的

- 作答回顧：新工具的面向名稱、選項文字照新題庫；「尚未稳定的题目」（現行 `reportCopy.ts` 逐族的）換成：選了最差那一檔或倒數第二檔的題。
- `SXK-QOL` 一段、氣質一段（九向度的高／低，用「偏向」的說法，不用好壞）；兩者都不進九宮格。
- TIC 紅旗、EMO 功能影響高：報告最上方一行轉介句（字句待客戶，R-3 同一題）。
- 「三个月后重评」等既有段落不動。
