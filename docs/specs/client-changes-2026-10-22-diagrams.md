- 「報告頁」不再有生成前的空殼，也沒有「T1 結論頁」（ADR-0014）。交卷到看到報告中間只有「生成中」。
- 訓練計劃那條路做完 T1 就能看影片（T1 推定）；T2 是讓下一期更準，不是必要。
- 代填的家長不走 T1，見第 4 張圖。

## 2. 居家訓練使用權（狀態圖）

取代 ADR-0012 的「先 T2、再線上干預收費站」兩道閘門。

```mermaid
stateDiagram-v2
  [*] --> 沒有
  沒有 --> 有效: 付款買訓練計劃
  沒有 --> 有效: 用掉兌換碼
  沒有 --> 有效: 推薦人代填（算一組兌換碼）
  沒有 --> 有效: 買 T2 附送一個月
  有效 --> 有效: 續買／再兌換（到期日往後加）
  有效 --> 到期: 到期日過了
  到期 --> 有效: 續買／再兌換
  note right of 有效
    到期日 ＝ 起算日＋長度
    一個月＝4 週、三個月＝12 週（一期）、六個月＝24 週（兩期）
    還在有效期內再買：從原到期日往後加，不重疊
  end note
  note right of 到期
    打卡紀錄、報告照樣看得到
    每週活動、示範片庫、單支活動、打卡端點 403
  end note
```

## 3. 推薦人、兌換碼與家長（類別圖）

```mermaid
classDiagram
  direction LR
  class 合作公司 {
    slug
    名稱
    logo_url
  }
  class 推薦人 {
    名稱
    手機號
    類型：渠道商｜治療師
    後台帳號
  }
  class 兌換碼批次 {
    產生時間
    張數
    計劃長度：1｜3｜6 個月
    產生者（全域管理員）
  }
  class 兌換碼 {
    碼（只存雜湊＋末四碼）
    狀態：未用｜已用｜作廢
    用掉的時間
  }
  class 家長 {
    手機號
    歸屬（合作公司或未歸屬）
  }
  class 推薦綁定 {
    綁定時間
    來源：兌換碼｜代填
  }
  class 居家訓練使用權 {
    起算日
    到期日
    來源：付款｜兌換碼｜代填｜T2 附送
  }
  class 代填結果 {
    九個方面的紅黃綠
    發現標籤（★）
    填寫時間
  }

  合作公司 "0..1" -- "*" 推薦人 : 隸屬（可不屬於任何一家）
  合作公司 "0..1" -- "*" 家長 : 歸屬（進站連結決定，不可逆）
  推薦人 "1" -- "*" 兌換碼批次
  兌換碼批次 "1" -- "*" 兌換碼
  兌換碼 "0..1" -- "0..1" 家長 : 用掉
  推薦人 "1" -- "*" 推薦綁定
  家長 "1" -- "0..1" 推薦綁定 : 第一次綁定就固定
  家長 "1" -- "*" 居家訓練使用權
  推薦人 "1" -- "*" 代填結果
  家長 "1" -- "0..1" 代填結果 : 最新一份
```

要點：
- **歸屬**（合作公司）與**推薦綁定**（推薦人）是兩件事：一位家長可以從醫院 A 的連結進來（歸屬醫院 A），用的是渠道商 B 的兌換碼（綁推薦人 B）。
- 家長已經綁了推薦人，再用另一位推薦人的兌換碼：照樣拿到使用權，**綁定不變**；這一組碼的佣金歸誰由對帳表看「碼屬於誰」，不看綁定。
- 兌換碼只存雜湊（與 `handoff_codes` 同一套做法），後台產生的當下顯示一次、可匯出。

## 4. 推薦人代填（序列圖）

```mermaid
sequenceDiagram
  actor R as 推薦人（治療師）
  participant Admin as 後台
  participant API as 伺服器
  participant DB as 資料庫
  actor P as 家長

  R->>Admin: 輸入家長手機號
  Admin->>API: 找家長（只在自己名下＋未綁定的範圍）
  API->>DB: 以（歸屬，手機號）找
  alt 找不到
    API->>DB: 建帳號（未歸屬或推薦人的公司）
  end
  R->>Admin: 孩子姓名／生日／性別<br/>九個方面紅黃綠＋勾標籤<br/>選計劃長度
  Admin->>API: 送出代填
  API->>DB: 寫代填結果、用掉一組這位推薦人的兌換碼、<br/>綁定（若還沒綁）、發使用權
  API-->>Admin: 完成
  P->>API: 手機號登入
  API-->>P: 首頁 → 居家訓練（不必作答）<br/>九宮格標「由治疗师填写」
```

## 5. 交卷即生成報告（序列圖，ADR-0014）

```mermaid
sequenceDiagram
  actor P as 家長
  participant UI as T1 問卷
  participant API as 伺服器
  participant AI as 模型（Qwen→豆包→DashScope→Gemini）

  P->>UI: 答完最後一題（補充資料）按「生成报告」
  UI->>API: 存 T1 成績（/api/db/save）
  UI->>API: POST /api/report
  UI-->>P: 生成中（報告頁骨架）
  API->>AI: 逐題作答＋提示
  alt 驗證通過
    AI-->>API: 報告
  else 驗證不過或全部失敗
    API->>API: 依作答組模板
  end
  API-->>UI: 報告
  UI->>API: 存報告快照（reportHistory）
  UI-->>P: 報告頁：首席专家结论、雷達圖、T2 深度评估入口
```

注意：`/api/report` 掛在 `aiLimiter` 之下。以前要按兩次才叫 AI，現在每次交卷都叫，限流的額度要在規格裡重新看。

## 6. 規格之間的相依

```mermaid
flowchart LR
  S1[規格一 畫面與文案] --> S3[規格三 訓練計劃與推薦人]
  S2[規格二 開屏與素材<br/>含 A 的合作公司] --> S3
```

規格三的「推薦人隸屬合作公司」要等規格二在 A 開了合作公司；規格三的訓練計劃頁與首頁卡片的去向要等規格一改完首頁。規格一與規格二可以平行。
