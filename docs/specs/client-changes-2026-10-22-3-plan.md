## Problem Statement

客戶要「先付費後評估」：家長被居家訓練吸引進來，先買一段訓練計劃，再做評估、看影片。現在只有一條路——T1 免費、依紅燈買 T2、T2 報告之後才碰得到線上干預，而線上干預一旦打開就永久免費，沒有可以賣的「一段時間」。微信支付還沒開通，客戶想先用兌換碼收錢；渠道商與治療師幫忙推廣，要能追蹤哪些家長是誰帶來的、對帳算佣金。線下個案的治療師已經清楚孩子狀況，不想讓家長重做評估，只想直接推給家長對應的影片。

## Solution

- 新商品「訓練計劃」：一個月、三個月、六個月。首頁「线上家庭个性化训练」點進去，沒有使用權的家長先看到訓練計劃頁；買了（微信支付，或輸入兌換碼）之後 T1、T2 都免費，做完 T1 就開始推影片。
- 原來那條路照舊：T1 免費、依紅燈（或自己勾）買 T2；第一次拿到 T2 報告附送一個月居家訓練，之後要繼續就買訓練計劃。
- 居家訓練（每週活動、示範片庫、打卡、提醒）只看一件事：有沒有一份還沒到期的「居家訓練使用權」。
- 後台：全域管理員建推薦人帳號（渠道商、治療師），替推薦人產生一批兌換碼；推薦人登入後台看得到自己的碼與自己名下的家長；家長用掉一組碼就自動綁到那位推薦人。全域管理員可以匯出兌換碼的使用明細對帳。
- 代填：推薦人在後台輸入家長手機號、孩子資料，九個方面選紅黃綠、勾標籤、選方案長度；家長登入後直接到居家訓練，不必作答。

## User Stories

1. 作為家長，我想點「线上家庭个性化训练」先看到一個月／三個月／六個月三種方案和價錢，這樣我知道要付多少。
2. 作為家長，我想每個方案有一句說明（重點針對什麼），這樣我知道差在哪。
3. 作為家長，我想在方案頁角落找到「兑换码」入口，這樣拿到碼的我不必付錢。
4. 作為家長，我想輸入兌換碼後馬上看到「已开通，到 X 月 X 日」，這樣我知道成功了、用到哪天。
5. 作為家長，我想輸錯碼時看到「兑换码不正确或已使用」，這樣我知道要找誰問。
6. 作為家長，我想微信支付還沒開通時，付款按鈕寫「暂未开放」而不是點了出錯。
7. 作為買了訓練計劃的家長，我想接著做 T1，做完馬上看到這週的活動，這樣當天就能開始練。
8. 作為買了訓練計劃的家長，我想 T2 深度評估不用另外付錢，這樣我願意多做幾份讓推薦更準。
9. 作為買了訓練計劃的家長，我想做了 T2 之後，下一期的活動照 T2 的結果排，這樣越練越準。
10. 作為走原路的家長，我想 T1 免費、依紅燈數量買 T2，跟現在一樣。
11. 作為走原路的家長，我想自己勾要深入的方面（例如只勾四個），照勾的數量付費，這樣我可以先做我最擔心的。
12. 作為走原路的家長，我想第一次拿到 T2 報告就附送一個月居家訓練，這樣我馬上能試。
13. 作為居家訓練快到期的家長，我想在居家訓練頁看到「还剩 N 天」和續買入口，這樣不會突然斷掉。
14. 作為到期的家長，我想以前的報告、打卡紀錄照樣看得到，只是不能再開新的活動。
15. 作為還沒到期就續買的家長，我想新的天數接在原來的到期日後面，這樣不會浪費。
16. 作為森心康，我想一個月＝4 週、三個月＝一期 12 週、六個月＝兩期，這樣跟推送規則排期對得上。
17. 作為全域管理員，我想建推薦人帳號（名稱、手機號、渠道商或治療師、可選隸屬某家合作公司），這樣推薦人能登入後台。
18. 作為全域管理員，我想替某位推薦人一次產生 N 組兌換碼並選方案長度，這樣可以交給他發。
19. 作為全域管理員或推薦人，我想在後台看到、複製、匯出還沒用的碼，這樣隨時能拿去發。
20. 作為全域管理員，我想作廢某一組還沒用的碼，這樣發錯了收得回來。
21. 作為推薦人，我只想看到綁在我名下的家長和我的碼，這樣不會看到別人的。
22. 作為推薦人，我想看到每位家長用了哪一組碼、什麼時候、到期日，這樣我能跟進。
23. 作為全域管理員，我想匯出兌換碼使用明細（推薦人、碼、方案、家長、使用時間），每次匯出都有紀錄，這樣能對帳算佣金。
24. 作為森心康，我想家長第一次用掉某位推薦人的碼就綁到他名下、之後不換，這樣佣金歸屬不會被搶。
25. 作為已經綁了推薦人 A 的家長，我想再用推薦人 B 的碼仍然拿得到使用權（綁定不變），這樣我不會被擋。
26. 作為治療師，我想在後台輸入家長手機號、孩子姓名生日性別，九個方面選紅黃綠並勾標籤，選方案長度，送出就好，這樣家長不必重做評估。
27. 作為治療師，我想代填用掉我的一組兌換碼，這樣對帳跟我發出去的碼一致。
28. 作為代填過的家長，我想用那支手機號登入就直接看到居家訓練，九宮格標「由治疗师填写」，這樣我知道結果是治療師給的。
29. 作為代填過的家長，我想之後仍可以自己做 T1、T2，做了以後照我自己的結果排下一期。
30. 作為治療師，我想再代填一次時覆蓋成新的結果，這樣孩子進步了可以調整。
31. 作為治療師，我不能替已經綁在別的推薦人名下的家長代填，這樣不會搶到別人的個案。
32. 作為森心康，我想兌換碼猜不到、同一個來源猜錯太多次就被擋，這樣不會被暴力試碼。
33. 作為維運，我想整批功能有一個開關、預設關，關著時一切跟現在一樣。
34. 作為維運，我想遷移只加表加欄位，退回程式碼不必退資料庫。

## Implementation Decisions

- **開關**：`TRAINING_PLAN`（只收 `1`/`true`/`0`/`false`，認不得起不來），要同時開 `TRAINING_PUSH_V3`，否則起不來。只在專案 A；B 設了不生效。關著時線上干預照 ADR-0012 的兩道閘門。
- **居家訓練使用權**（新純函式模組＋新表 `training_passes`）：一列＝一段使用權：家長、起日、迄日（日期，Asia/Shanghai）、月數、來源（`payment`／`code`／`proxy`／`t2_bonus`）、付款或兌換碼的參照。「今天有沒有效」＝有一列起日 ≤ 今天 ≤ 迄日。新增一段時起日＝max(今天, 最晚的迄日＋1)，長度 1→28 天、3→84 天、6→168 天（對齊一期 12 週）。
- **閘門**：開關開著時，線上干預那幾支端點（每週活動、整期計劃、片庫、單支活動、打卡、提醒）只看使用權，取代「先 T2、再線上干預收費站」；T2 的閘門多認「有效的使用權」＝T2 已解鎖（訓練計劃包含 T2）。`/api/unlocks` 多回 `trainingPass: {active, endsOn}`。線上干預端點分類的護欄測試照舊要點名每一支。
- **T2 附送一個月**：家長有任何一份 T2 報告、從沒拿過 `t2_bonus` 時，第一次查使用權就發一段 1 個月（起日今天）。這條同時涵蓋「開關打開之前就買過 T2」的家長。
- **訓練計劃頁**：家長端新畫面，三張方案卡（月數、價錢、一句說明）、角落「兑换码」入口。價錢由伺服器設定 `TRAINING_PLAN_PRICES_FEN`（`1:…,3:…,6:…`，三個都要有，認不得起不來）；方案說明的字由客戶提供，先放暫採字。首頁居家訓練卡與報告頁、T2 報告的續買入口：沒有有效使用權→訓練計劃頁；有→居家訓練頁。
- **付款**：沿用既有付款流程，`payments` 的範圍多一個 `plan`、多一欄月數（遷移只加）；成功回調發一段 `payment` 使用權。微信支付沒設定齊時方案卡的付款鈕不能按、寫「暂未开放」，只剩兌換碼。免費期間開關（`PAYWALL_FREE`）只影響 T2，不讓居家訓練變免費。
- **兌換碼**（新表 `redeem_batches`、`redeem_codes`）：一批＝推薦人、月數、張數、建立者、時間；一組碼＝批次、碼、狀態（未用／已用／作廢）、使用家長、使用時間。碼 10 碼（去掉易混字元的 base32，顯示成 `XXXX-XXXX-XX`），**存明碼**（客服與推薦人要能在後台再拿出來發；與交接碼只存雜湊不同，因為交接碼不必再顯示）。只有全域管理員與該碼所屬的推薦人看得到明碼。兌換端點：要登入；碼大小寫與分隔符不拘；原子地把「未用」改「已用」（同一組碼兩人同時兌只有一人成功）；成功發一段 `code` 使用權、若家長還沒綁定就綁到該碼的推薦人；任何失敗都是同一個錯誤訊息。兌換有獨立限流（每位家長、每個來源）。
- **推薦人**（新表 `referrers`：後台帳號、名稱、手機號、類型渠道商／治療師、可選合作公司、啟用）：`admin_users` 的角色多一個 `referrer`（遷移只加列舉值）。推薦人登入同一個管理中心，只看到「我的家长」「我的兑换码」「代填」三個分頁；家長列表的範圍條件是「綁在我名下」。`adminScope` 的護欄把推薦人的範圍納入，新表都要歸類。
- **推薦綁定**（新表 `referrer_bindings`：家長為主鍵、推薦人、來源兌換碼／代填、參照、時間）：第一次就固定，之後不改。
- **代填**：推薦人在後台以手機號找家長：在自己名下或還沒綁定的才行，綁在別人名下回「这位家长已由其他推荐人服务」；找不到就建帳號，歸屬＝推薦人的合作公司（沒有就未歸屬，以（歸屬，手機號）為鍵，同登入）。填孩子姓名、生日、性別（孩子已存在則可改）；九個方面各選紅黃綠；勾發現標籤（只給 ★ 那一組，顯示中文短名）；選月數。送出時在同一個交易裡：寫一份評估結果快照（見下）、用掉該推薦人一組同月數的未用碼（沒有就先為他產生一組再用掉，對帳表上一樣是一組）、綁定（若還沒綁）、發一段 `proxy` 使用權。再代填一次覆蓋成新的快照（舊的留著），不再扣碼。
- **評估結果快照的三種來源**（不改推送規則）：線上干預的一期是掛在一份評估結果快照上排的。現有的快照是量表交卷後生成的；新增兩種：「只有 T1」（訓練計劃的家長做完 T1、還沒做 T2 時自動產生，九個方面都是 T1 推定）與「代填」（治療師給的紅黃綠當作 T2 分級、勾的標籤當發現標籤）。三種存在同一張表、用題庫版本欄區分，推送規則與每週活動一行不動。報告頁看到代填的快照畫九宮格與「由治疗师填写」，沒有作答回顧與 AI 敘述。
- **對帳匯出**：全域管理員一支 `.xlsx` 匯出（沿用彙總表的 exceljs 與 `admin_exports` 紀錄）：推薦人、類型、碼、月數、狀態、使用家長（手機號）、使用時間、使用權迄日。記不下紀錄就 500 不給檔（同彙總表）。

## Testing Decisions

- 好的測試只看外部行為：給一串使用權與今天，回有沒有效、到哪天；打兌換端點，看回應、表裡多了什麼、兩人同時兌只有一人成功。
- **使用權**：純函式測試——續買接在迄日之後、過期後再買從今天起、三種長度的天數、跨月與跨年、Asia/Shanghai 換日。
- **閘門**：HTTP 測試（前例：線上干預收費站的路由分類測試、T2 付費閘門的 http 測試）——開關開著：沒有使用權 403、有效 200、到期 403；有 T2 報告的家長第一次查拿到附送一個月且只拿一次；T2 端點對有使用權的家長放行。開關關著：一切照現在。
- **兌換碼**：產生的碼格式與不重複、大小寫與分隔符不拘、已用／作廢／不存在同一個錯誤、併發只有一人成功、綁定第一次固定、限流。
- **推薦人與代填**：HTTP 測試（前例：後台範圍的 http 與結構測試）——推薦人只拿到自己名下的家長與碼、不能代填別人的家長、代填建帳號的歸屬、代填後家長拿得到每週活動且九宮格是治療師給的顏色、再代填覆蓋且不扣碼。
- **快照三種來源**：推送規則吃「只有 T1」與「代填」兩種快照排得出一期（前例：推送規則與一期生命週期的測試）。
- **遷移**：`deploy/schema.sql` 與遷移檔一致的結構測試（前例：活動庫與交接表的 schema 護欄）。
- 畫面：訓練計劃頁、兌換、居家訓練到期提示、後台三個分頁用 vite harness 實機看。

## Out of Scope

- 微信支付本身的開通與商戶設定；佣金自動分帳（要另開通服務商）。
- 註冊時填推薦碼（使用者 10/22：只有兌換碼一種）。
- 推薦人看得到家長的作答細節以外的東西（例如改家長資料）；推薦人自己產生兌換碼（只有全域管理員能產）。
- 退款流程。
- 合併量表（等客戶提供）。
