# 專案 A：家長的身分只看手機號，「現在誰服務」另外記、可以改派

客戶要讓治療師也能拿進站連結、合作公司也能代填。一家機構可以有好幾位治療師：他們用機構的連結，每個人也有自己的個人連結；治療師登入後只看標注給自己的家長。另外，已經註冊的家長要能轉給某位治療師，也要能換治療師。

現行模型做不到。**歸屬**同時是家長身分的一半（ADR-0002：歸屬＋手機號），也代表哪家公司服務這位家長，所以換一家等於換了一個人。推薦人綁定則從第一次綁上就不能改（客戶 10/22 規格）。正式站 A 已經出了事：同一位家長先從公網註冊（#9，未歸屬，報告、訂單、T2 作答都在這裡），後來從治療師的 `?c=` 進來，又多開了一個帳號（#13）。治療師那邊看不到這位家長以前的資料。

使用者 2026-11-23 逐題確認，**只在專案 A**這樣決定：

1. **身分只看手機號**：一支手機號就是一位家長。不管點哪個單位或推薦人的連結登入，都是同一個帳號。ADR-0002 在專案 A 的部分作廢，專案 B 照舊。
2. **篩查渠道**記家長最早從哪裡來，固定不改，只是紀錄。
3. **服務關係**另外存、**可以改派**，每次改都留紀錄（誰改的、從誰改成誰、什麼時間、是不是家長自己換的）。後台誰看得到哪位家長、頁首 Logo、新訂單的清分對方，全部看服務關係。換掉之後，原來的單位與推薦人就看不到這位家長。
4. **合作公司改名「合作單位」**，分兩類：機構（底下可以有好幾位推薦人）、個人治療師（恰好一位推薦人，他同時是單位管理者）。
5. **推薦人就是治療師**，一律屬於某個合作單位。不再分渠道商與治療師，原本的渠道商也走服務關係。現在的「公司成員」帳號就是**單位管理者**。
6. **改派權限**：全域管理員什麼都能改；單位管理者只能改自己單位裡的；推薦人不能手動認領。家長從連結或兌換碼自己掛上時，還沒有服務關係就直接掛上；已經有了就先跳提示問家長，家長選換才改。
7. **兌換碼一起分銷**：碼發給推薦人，同時算推薦人與所屬單位，佣金照清分比例分（預設機構 20%、推薦人 80%）。代填用掉的碼也一樣。家長用了誰的碼，就標注給誰。

## 為什麼

- **換人只改一列**：報告、訂單、使用權、T2 作答都掛在家長帳號上，一行不搬。換治療師、換單位、先註冊後來才找治療師，三種情況都只是改服務關係。
- **清分本來就不怕改派**：ADR-0016 在開單那一刻把對方記進訂單，所以舊單照舊算，只有新單跟著現在的服務關係。
- **身分不再綁單位**：重複帳號就不會再發生。ADR-0002 當初擔心的三件事（B 公司看不到、檔案被覆蓋、A 公司看到 B 的結果），現在交給服務關係處理：一位家長同一時間只由一個單位服務，換掉就看不到。

## 考慮過、沒採用的

- **獨立治療師開成一家合作公司就好**（2026-11-07 的做法）：營運上可行，但換治療師就等於換公司，也就是換一個人；而且公司成員帳號沒有兌換碼與代填。
- **保留推薦人，只給渠道商用**：使用者不要兩套名字。代價是渠道商帶來的家長一旦改派給別人，渠道商就看不到、也分不到新單，客戶接受。
- **家長點了別人的連結就自動換過去**：家長可能被別人「搶」走，所以改成先問家長。

## 後果

- **遷移**：
  - 綁了推薦人的家長：服務關係算推薦人和他的單位，就算帳號原本歸屬另一家公司也一樣。
  - 只歸屬某家公司的家長：落在那個單位，還沒標注推薦人。
  - 未歸屬的家長：沒有服務關係，是森心康直屬。
  - 沒隸屬公司的推薦人：每人轉成一個個人治療師單位。「杨智翔」那家公司也轉成個人治療師單位。
  - 正式站重複的 #9／#13：保留 #9，把 #13 的使用權與綁定搬過去，再停用 #13。
- **舊規則作廢**：推薦人「第一次綁定就固定、不改」（`referrer_bindings` 以家長為主鍵、10/22 規格），以及 ADR-0016「誰是對方」的暫採規則，都改成看服務關係。
- **先止血**：在這份 ADR 做完之前，可以先只做第 1 點（登入只用手機號找帳號，包在開關後面）。代價是家長留在原來的歸屬，治療師那邊暫時看不到，要等服務關係做好或由後台補標注。
- 專案 B 的歸屬、隔離、ADR-0002 一個字都不變。
