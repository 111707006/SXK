# T2 每個被標記的維度只出一份問卷，不照客戶推薦規格書加第二份；診斷不進推薦

客戶 10/06 的《T2 量表推荐规则规格书》要求：重點維度（紅旗、診斷核心、明顯落後）配第二份（步驟 9「深度」）、
份數不到 3 份要補足（步驟 11）、有中度以上加生活質量基線（步驟 10）、T1 特定題目觸發時規則必推 M-CHAT／情緒篩查／抽動量表
（R1、R3、R4），家長填了診斷時再推該診斷的必選量表。我們**不照做**這幾條（使用者 2026-10-08，待問表 R-33）：

- **每個被標記的維度只出一份**，就是照月齡從首選順序挑出來的那一份；全部必做，沒有選做、沒有加測。
  一份涵蓋好幾個維度（例如分齡發育綜合評估）可以，那幾個維度都算已經有一份。全面落後時的跨領域量表（R5）照留 —— 它本身就是「一份」。
- **合併（2026-10-08 補充）**：66 個月以下，動作、語言、認知、社交有 3 個以上被標記、而且全是黃燈（家長在 T1 報告上看到的顏色）
  → 用一份分齡發育綜合評估涵蓋這幾個維度；只要有一個紅燈就不合併、照每維一份（`asq3Merge`）。
- **規則觸發不推問卷，改成提示**：T1 社交溝通警訊題（R1）、情緒安全題（R3）、家長說有抽動（R4）觸發時，入口與報告最上方各出一句提示，
  附預約專家的按鈕。社交維度用社會能力發展量表，不換成 M-CHAT。
- **診斷不進推薦**：孩子資料「补充资料」拿掉診斷那一題；引擎一律當作沒有診斷（呼應 2026-09-29 拿掉 T2 入口的「诊断方向」）。

## 為什麼

- 使用者自 9/29 起的方向一貫是「每個維度每個年齡一份表單」，題量要讓家長在手機上一次做得完。
- 第二份（深度）對報告與線上干預的幫助很小：判定取最重那一份，線上干預 v3 每個維度只看一個 0–3。
- 社交選社會能力發展量表、不選 M-CHAT：M-CHAT 是 20 題是／否，沒有面向，報告講不出哪一面弱、作答回顧是空的；
  它是自閉症篩查，報告不能出現那個詞；分數高時本該接第二階段訪談，而 T2 沒有治療師（memory `t2-has-no-clinician`）。
  M-CHAT 想抓的訊號由提示＋預約接住。
- 診斷是家長自述，T2 沒有人能核實，也是使用者 9/29 明確拿掉的東西。

## 怎麼做

引擎（`src/t2/recommend/engine.ts`）多一個選項 `onePerDimension`：不加 R1／R3／R4 的問卷、不跑診斷必選、社交的首選順序不因警訊換成 M-CHAT、
跳過步驟 9–11。**預設不開** —— 客戶規格書的逐格測試（30 格標準表、10 個案例）照舊對得上；`runRecommendation` 開著它跑。
要回到客戶規則：把 `ONE_TOOL_PER_DIMENSION` 改成 `false`、把診斷那一題放回去。

## 什麼時候要回頭

- 客戶堅持深度評估要有第二份，且願意接受家長的題量。
- T2 有治療師參與（M-CHAT 第二階段、診斷可核實）。
