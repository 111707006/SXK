# T2 完整版題庫照舊抽資料、伺服器重算，不內嵌客戶的評估網頁

客戶 9/23 的完整版工具包附了一份給 IT 的接入說明書（SXK-IT-001）。它建議的接法是：把每支 HTML 放進 iframe，
收工具送出的 `postMessage`（`{grade, score, note}`）、存工具自己匯出的 JSON；並明寫「不要在院内系统里重算分数或重画报告」。
我們**不照做**：繼續 9/08 那一版的做法 —— 腳本從 HTML 抽出題目與切點、伺服器照頁面的公式算分、作答畫面自己畫。

## 為什麼

- **頁面是給治療室用的。** 必填「评估人员／填表人」與個案姓名，混著治療師才答得了的段落（排除因素、紅旗、情境、觀察活動、M-CHAT 訪談）；
  我們的 T2 是家長在手機上自己填（memory `t2-has-no-clinician`）。
- **頁面的報告字不過客戶自己的《家长报告用语对照表》**，分段名稱就有「明显落后」。內嵌就等於把禁字原樣給家長看。
- **`postMessage` 不能直接用。** 7 支的回傳分段跟頁面上不是同一套切點，VOC 永遠不送「重度」，氣質不送；`grade` 是中文字串、`score` 沒有共同量尺
  （說明書自己說的）。不論內嵌與否，對到 0–3 這一步都得我們做。
- **付費報告的判定要伺服器說了算**，不能信瀏覽器回報（#57 就是為此改成伺服器算分）。
- **抽題一向不執行客戶的程式碼**（`scripts/t2/literals.ts`）；內嵌就是在家長的瀏覽器裡跑它。

## 代價與補救

說明書擋的是「重算算錯、外觀看不出來」。我們的補救：常數一律腳本抽、探針讀不到就停（客戶換版重跑會炸）；計分照頁面公式搬，
每支在每個切點兩側各一組測試，註明出自頁面哪一行；把重算這件事與逐支的 0–3 對照表交給客戶看（R-7、R-15）。

## 什麼時候要回頭

- 客戶明確要求「家長端必須用原頁面」（例如授權條款要求原頁面原樣呈現 —— M-CHAT、SNAP-IV、CHEXI 的授權，R-26）。
- 客戶把頁面改成家長版（拿掉治療師欄位、報告字過對照表、回傳一致的 0–3）。那時內嵌的成本會比維護 24 份配方低。

## 考慮過的

- **內嵌＋收 `postMessage`**：上面那些理由。
- **內嵌但伺服器另外重算核對**：兩套都要維護，比只做一套貴，而且兩者不一致時家長看到的是哪一個仍要決定。
