# 後台顯示的是家長的報告本體，匯出改為列印同一份

客戶 2026-09-11 看後台的家長詳情，問「前面（家長端）有雷達圖那些，後台都看不到嗎」。當時後台的詳情與匯出都是一張九維度表格加 AI 文字，一張圖都沒有。本次 grilling 定案：**客服看到的就是家長手機上看到的那一頁**，不另做一個「給專家判讀」的後台版。

## 決定

- **報告本體抽成一個只吃資料的共用元件**，家長端與後台用同一個。家長端的 `AnalysisReport` 保留生成、預約、列印等動作，中間嵌入本體；家長端專屬的兩塊（語言專項入口、掃碼帶走卡）用插槽放回原位，順序不變。
- **要讀的區塊全進後台，要按的不進**：生成／重新評估、語言專項入口、掃碼帶走卡、預約表單都不進。後台既有的「專家預約」區塊顯示的是實際送出的預約，留著。
- **後台讀的是報告（快照），不是篩查結果（現況）。** 列表照篩查結果亮燈，詳情照最近一份報告；兩者分岔時詳情頂端提示並附上目前的篩查結果表格。規則本身寫在 `CONTEXT.md`「報告」條目底下。
- **匯出改為在新分頁開同一個報告本體並叫出列印。** 後台的 `/parents/:id/export` 路由與彈出視窗被擋時的下載備援一併移除；`exportView.ts` 只剩家長掃碼頁（`/r/:token`）在用。
- **圖表的顏色一律照篩查判定（嚴重度）上色**，關注分只當雷達圖的軸值。規則寫在 `CONTEXT.md`「關注分」條目底下。
- 報告標題的「监测号」改名「报告编号」，由報告 id 算出，同一份報告永遠同一號。原本每次渲染取當下時間的後六位，家長自己重開都不一樣。

## 為什麼是「同一頁」而不是「給專家的版本」

後台的讀者是客服，工作是接家長的電話。家長說「我看到那個儀表 72%」，客服得看得到同一個 72%。這個目的決定了**裝飾性的圖也照放**——發育軌跡預測圖的四個數字是寫死的（62→74→87→95，每個孩子一樣），百分位條沒有常模；它們出現在後台，是因為家長看得到它們，不是因為它們有臨床意義。

⚠️ **不要在後台把它們「修掉」。** 看到後台畫著一張每個孩子都一樣的曲線，正確的反應是去改共用元件（兩邊一起變），或去問產品端那張圖該不該存在——不是只在後台拿掉。後台一旦與家長端分岔，這份決定就沒了。

## 為什麼匯出改為列印，不改伺服器端畫圖

匯出頁是伺服器拼字串出的純 HTML，沒有 React、沒有 Tailwind。要讓它「長一樣」，等於用字串再實作一次整份報告，之後每次改報告都要改兩處。改為列印抽屜裡那個本體，紙上的樣子與螢幕上一定一致，也與家長端「打印报告」走同一條路。

當初把匯出做成伺服器端、與詳情共用 `getParentDetail` 的理由（issue #8：不讓匯出成為繞過公司範圍的第二條取資料路徑）仍然成立——抽屜的資料就是同一支端點回的，新分頁也只是再呼叫一次同一支。

## 後果

- **印出來變長很多。** 舊匯出是一到兩頁的表格，新的是整份報告。產品端知情並選擇「家長拿到的那份」。
- 家長掃碼那一頁**不動**，仍是伺服器出的表格版。要讓它也長一樣，得把它改成 React 頁面（失去「不靠 JS 也打得開」）或另寫一套字串畫圖；兩者都不在本次範圍。
- 專案 A 的深度評估報告（T2/T3，`SpecializedReportView`）不在本次範圍，後台只放篩查報告。
- 後台 `reportHistory` 的型別改用 `AssessmentRecord[]`，不再手寫子集——資料一直是完整的，只是型別漏了 `child`、`scores`、`criticalMetrics`。
- 改用嚴重度上色之後，得分 4–5 的維度在報告的圖裡從黃變紅、6–7 從綠變黃。**這是預期結果，不是回歸。**
