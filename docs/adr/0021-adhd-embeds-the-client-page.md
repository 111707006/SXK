# 成人 ADHD 直接用客戶的頁面，伺服器不重算分數

成人 ADHD 篩查（`APP_MODE=adhd`，arscreen.cn，設計 `docs/specs/adhd-product-design.md`）的作答與報告，**原樣用客戶的單頁 HTML**
（`ADHD/成人ADHD筛查版_20261111.html`，一個位元組不改），只在 `</body>` 前插一行 script（`src/adhd/bridge.js`）：
擋未登入、走到報告時把頁面自己匯出的個案 JSON（`casePayload()`，含頁面算的分數與結論）存到伺服器、後台與受評者只讀回看。
伺服器只檢查形狀，**不重算**。

這與 ADR-0010（T2 完整版：抽題、伺服器重算、不內嵌）相反。

## 為什麼這次可以

ADR-0010 擋內嵌的理由，這裡一條都不成立：

- **頁面就是給本人填的。** ADR-0010 的頁面混著治療師才答得了的欄位；這一份是成人自評＋可選的知情人他評，填的人就是要用頁面的人。
- **沒有錢、沒有解鎖跟著分數走。** T2 的判定決定付費報告的內容，所以要伺服器說了算；這裡存下的結論只給本人回看、給後台看。
  受評者竄改自己送出的結論，影響的只有他自己那一筆。
- **使用者要的是「一字不改」**（2026-11-23，主 session 定的折衷：照 B 的登入與後台，作答與報告沿用客戶頁面）。重算就是維護第二套計分，
  兩套不一致時還要決定家長看哪一個。
- **客戶頁面的報告字是描述性的**（「仅描述回答频率，不代表诊断」），沒有 ADR-0010 那種踩用語對照表的分級字。

## 代價與補救

- 結論可以被竄改 → 伺服器仍擋形狀（題數、值域、結論代碼、姓名），形狀不符 400、不落表（`src/adhd/payload.ts`）。
- 客戶換版可能靜靜壞掉 → bridge 依賴的全域變數列成探針（`src/adhd/page.ts`），少一個建置與伺服器都起不來（`test/adhdPage.test.ts`）。
- 在受評者的瀏覽器裡跑客戶的程式碼 → 原本就是這樣（現在的 sxkscreen.com/adhd/ 就是這份頁面）；它不載任何外部資源。
  `CSP_MODE=enforce` 會擋掉頁面的內嵌 script，ADHD 站要開 CSP 得另外給 `/assess/` 一組規則。
- 共用裝置上的本機草稿 → bridge 換人登入就清、只讀檢視不碰本機儲存、外殼登出也清。

## 什麼時候要回頭

- 結論開始決定收費、解鎖或推送（例如接上付費的深入評估）：分數要改由伺服器算，照 ADR-0010 的做法抽題重算。
- 客戶頁面改成要連外部服務、或報告字開始需要過用語對照表。
